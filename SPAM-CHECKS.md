> Обновление 5.13.0: после завершённой проверки с результатом `unknown` или `error` аккаунт доступен для продажи в категории «Спамблок не проверен» (`auto-CC-unverified`). Старые такие товары переводятся из `pending` при запуске. Статус сохраняется в снимке заказа; отсутствие ограничений не обещается. Первичная очередь `not_checked` остаётся скрытой, активная проверка блокирует покупку до завершения. Отключённые вручную целевые категории остаются отключёнными.

# Проверка спамблока

Бот проверяет свободные аккаунты через официальный `@SpamBot`: отправляет `/start` и ждёт новый ответ именно от этого бота. Телефон и Telegram ID сессии сверяются с товаром до отправки. Если сам SpamBot заблокирован в проверяемом аккаунте, после ответа Telegram о блокировке бот выполняет разблокировку только подтверждённого `@SpamBot`, повторяет `/start` один раз и ждёт свежий ответ. Это не снимает спам-ограничения аккаунта и не подаёт апелляцию. FloodWait при разблокировке соблюдается.

Проверка не отправляет сообщения другим пользователям и не подаёт апелляции.

После добавления товара одиночной загрузкой, авторизацией или ZIP-импортом он автоматически попадает в очередь. Ранее загруженный остаток также проверяется после обновления. Очередь обрабатывает по одному аккаунту, когда работает основной процесс `bot.py`. Веб-сервер, запущенный отдельно для диагностики, очередь не обрабатывает.

Результаты:

| Статус | Значение |
| --- | --- |
| Не проверен | Очередь ещё не обработала аккаунт |
| Ограничений не обнаружено | Получен однозначный свежий ответ @SpamBot об отсутствии ограничений |
| Есть ограничения | @SpamBot сообщил об ограничениях, бессрочность не подтверждена |
| Вечный спамблок | @SpamBot явно подтвердил постоянное/бессрочное ограничение |
| Нужна повторная проверка | Новый ответ остался неизвестным или неоднозначным после повторного /start; аккаунт скрыт |
| Не удалось проверить | Ошибка авторизации, несовпадение профиля, сеть, таймаут либо FloodWait |

Дата и время показывают последнюю попытку проверки по Москве. Результат отражает состояние на этот момент; срок снятия ограничений не выдумывается. Распознаются известные русские и английские ответы. Полный текст переписки не сохраняется и не публикуется. При покупке статус и время фиксируются в снимке заказа.

Успешная проверка обновляется через 24 часа, неопределённый ответ — через час, ошибка — не раньше 15 минут. FloodWait откладывает повтор как минимум на указанный Telegram срок. Ручной повтор разрешён не чаще одного раза в 5 минут и не сокращает FloodWait.

В админке бота есть кнопка «Проверить спамблок всех аккаунтов», а в карточке товара — «Проверить спамблок». В Mini App: **Админка → Товары → Проверить**, либо «Проверить спамблок всех». Массовая команда требует подтверждения. В каталоге Mini App видимые карточки автоматически получают свежий статус примерно каждые 5 секунд, в том числе после загрузки следующих страниц. «Нет спамблока» показывается только при подтверждённом результате `clear`, «Есть спамблок» — при `limited`. Сеть, таймаут и неизвестный ответ не превращаются в отсутствие ограничений. При открытом подтверждении покупки фоновое обновление карточек не меняет показанные условия. Проверка через Telegram остаётся очередью: время ожидания зависит от её размера, сети и ограничений Telegram.

Проданные аккаунты исключены. Действующий резерв откладывает проверку; на время обращения к @SpamBot блокируются покупка, создание резерва и выдача аккаунта как замены. Проверка ограничена по времени, временная блокировка истекает через 2 минуты при аварийном завершении процесса. Запись результата привязана к тому же товару, сессии и уникальному заданию: старый ответ не перезаписывает новый.

## Обновление VPS

```sh
cd /opt/session-shope
git pull --ff-only origin main
sudo systemctl restart session-shope.service
```

Новых зависимостей нет. При запуске добавляются поля и индекс в `accounts`; старые товары начинают со статуса «Не проверен». Нужны существующие `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` и доступ VPS к Telegram. После обновления отправьте `/start` и заново откройте Mini App. Большой остаток обрабатывается последовательно; результат появляется после прохождения очереди.

## Проверки

```sh
python -m unittest discover -s tests
python tests/integration_spam.py
node tests/spam_browser.cjs
```

Интеграции используют одноразовую MySQL на `127.0.0.1:13307` и тестовый Mini App из `integration_miniapp.py --admin --serve`. Ответы Telegram заменены тестовыми объектами: из облачной среды реальный Telegram недоступен. Рабочие аккаунты и их сессии в тестах не используются.


## Автокатегории (5.11.0)

При нераспознанном свежем ответе проверка разблокирует только официальный @SpamBot, повторяет `/start` один раз и разбирает новый ответ на второй запрос. При FloodWait ожидание Telegram сохраняется; бесконечного цикла нет. Неизвестный язык, CAPTCHA или изменение формата нельзя достоверно объявить отсутствием ограничений.

Страна берётся из номера, полученного при проверке сессии. Одиночная загрузка, авторизация и ZIP сначала помещают товар в скрытую категорию «Чили 🇨🇱 · Проверка спамблока» (аналогично для других стран). В боте и импорте Mini App есть выбор «Авто: страна и спамблок». После проверки создаётся или используется категория:

- `Чили 🇨🇱 · Без спамблока` — только подтверждённый `clear`.
- `Чили 🇨🇱 · Вечный спамблок` — только явный `permanent`.
- `Чили 🇨🇱 · Есть ограничения` — ограничения подтверждены, бессрочность не установлена.

Неизвестные ответы, ошибки и неопределённая страна остаются скрыты. Непроверенный товар можно редактировать в админке; изменение цены не публикует его. Нельзя вручную поместить аккаунт с вечным спамблоком в автоматическую категорию чистых аккаунтов. Автоматическая проверка сохраняет вручную отключённые категории и не изменяет проданные товары или зафиксированные условия покупок. Ограничения РФ и Украины сохранены.

При первом обновлении оставшийся непроданный товар ставится на свежую проверку; старое название категории не считается доказательством. При активном резерве проверка откладывается. Для работы очереди нужен основной сервис `session-shope.service`, не только отдельный веб-сервер.

Номер товара теперь выводится без SBA: `#01`, `#02`, `#123`. Внутренний ID и ссылки не меняются; поиск понимает ранее скопированные номера. Администратор может устанавливать, добавлять и списывать баланс больше 10 000 ₽, включая отрицательные значения. Сохраняются журнал, права администратора, защита от повторной операции и предел точности базы ±9 999 999 999,99999999. Лимит новых счетов СБП 1–10 000 ₽ и ограничения цены товара/корзины остались отдельными правилами.

Дополнительные проверки: `tests/test_auto_categories.py`, `tests/integration_auto_categories.py` и `tests/auto_categories_browser.cjs` (первый скрипт с `--serve`). Все ответы Telegram и сессии в этих проверках синтетические.
