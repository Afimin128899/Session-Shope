# Mini App: категории, сообщения и администрирование

По команде владельца включены магазин для администраторов и отдельная
админ-панель `/admin-app`. Кнопка Mini App видна всем в главном меню бота.
Пока общий доступ закрыт, остальные пользователи видят «Только для админов».
Подпись и срок Telegram initData проверяются сервером на каждом API-запросе.
Права администратора берутся из существующего `ADMIN_IDS`.

В админ-панели раздел «Доступ Mini App» включает и закрывает магазин для всех.
Изменение сохраняется в MySQL как `settings.miniapp_public_access` и попадает
в журнал действий. Отсутствующая настройка означает закрытый доступ.
Перезапуск сохраняет выбранное администратором состояние; публикация этой
версии сама не включает общий доступ. Пользователь не может изменить настройку
или получить доступ к административным API.

## Интерфейс

Новый интерфейс находится в `miniapp/storefront_v2/`. Серо-чёрные поверхности,
очень тёмные синие кнопки, анимации нажатий, переходов, карточек и переписки.
При системном запросе уменьшения движения анимации отключаются.
Снизу — «Маркет», «Сообщения», «Профиль». Удалён нижний рекламно-информационный
блок с тарифами и проверочным словом. Документы доступны в профиле.
Используется новый набор баннеров SbandACCSbot. Круглые аватарки стран используют
существующие изображения флагов. Профиль показывает фото из подписанного Telegram
initData; для старых клиентов фото запрашивается через Bot API только для
подтверждённого текущего пользователя. При отсутствии фото остаётся инициал.

Каталог показывает категории по стране и статусу спамблока, включая пометку
«Вечный СБ». Фильтры «Авторег», «С отлегой», «Премиум» и поиск используют
существующие остатки. Пользователь сначала выбирает страну, затем категорию по спамблоку. У каждой
категории указана актуальная минимальная цена: «США Без спамблока»,
«США Вечный СБ», «США» для непроверенного результата. Временные ограничения
отображаются отдельной категорией. Свободный аккаунт
подбирается автоматически по минимальной доступной цене. Перед списанием
показывается итог. Сервер выдаёт краткоживущее предложение, привязанное к
пользователю; клиент не задаёт цену или ID аккаунта для новой покупки.
Используется прежняя транзакция покупки с повторной проверкой цены, гарантии,
спамблока, доступности и баланса. Данные доступны только владельцу заказа.
Кнопка «Получить код» доступна также прямо в заказе Mini App. Используется
прежний механизм чтения кода; сервер проверяет владельца, статус и наличие
рабочей сессии до и после ожидания. После возврата/завершения код не выдаётся;
повторное чтение остаётся доступным, пока сессия активна. Коды и сессии
не попадают в список товаров, журнал действий или общий кэш.

Корзины в новом интерфейсе нет. Рабочие HTTP-маршруты корзины удалены из
регистрации по умолчанию. Старые таблицы и общие функции не удалены, поскольку
массовая покупка в боте использует ту же инфраструктуру. `enable_cart=True`
оставлен для изолированных регрессионных фикстур; рабочий запуск его не передаёт.
Прежние статические исходники магазина сохранены в `miniapp/static/`.

## Переписка и загрузка аккаунтов

«Сообщения» — одна личная переписка пользователя с поддержкой, без тикетов.
Текст сохраняется в `direct_support_messages`, сообщения посторонних
пользователей недоступны. Есть подгрузка ранней истории и периодическое
обновление. Сообщения из Mini App уведомляют администраторов в боте; отвечать
можно из бота или административного раздела «Сообщения».
Текст и подписи сообщений, успешно переданных существующей прямой поддержкой
бота, также сохраняются; вложения представлены текстовой отметкой.
Старые переписки до установки версии не восстанавливаются из Telegram.
При недоступной доставке в Telegram переписка Mini App остаётся в базе.

В админке «Залив аккаунтов» принимает ZIP до 8 МБ и 100 аккаунтов .session.
Сначала выполняется существующая проверка архива и показывается предпросмотр.
Администратор выбирает готовые строки, задаёт цену, гарантию и при необходимости
известный пароль 2FA, затем явно публикует. Дубликаты и запрещённые номера
проверяются прежним сервером. Страны и категории спамблока определяются
существующей системой; клиент не может пометить аккаунт проверенным.
Публикация не запускает @SpamBot: товар доступен как непроверенный.
В разделе «Товары» есть кнопки «Проверить на спамблок» и запуска для всего
остатка. Проверки выполняются серверной очередью, только после явного запроса.
После результата автоматического ежедневного повтора нет; следующий запуск
снова требует кнопки. Сохраняются пятиминутный интервал, FloodWait, блокировки
проверяемых/зарезервированных аккаунтов и защита от устаревшего результата.
Если официальный @SpamBot заблокирован или ответ не распознан/не пришёл,
сервис разблокирует именно проверенного @SpamBot и делает одну повторную
попытку; ошибки авторизации и ограничения Telegram не выдаются за чистый статус.

В окне пополнения способы оплаты представлены отдельными кнопками.
Поля, выбранный метод и кнопки блокируются на время создания счёта.
Ошибки суммы, недоступность провайдера и результат проверки отображаются
под меню в этом окне. Обычного системного списка выбора больше нет.
Счёт и зачисление по-прежнему проверяются прежними платёжными интеграциями.

## Установка обновления

Существующий Python/MySQL стек, платёжные провайдеры, курсы, остатки и балансы
сохранены. При запуске `db.init_db()` добавляет таблицу переписки через
`CREATE TABLE IF NOT EXISTS`. Поле `accounts.spam_requested` отмечает только
явно запрошенные проверки. Старые первоначальные категории `auto-*-pending`
переносятся в непроверенное наличие без изменения цены или баланса.
Сохранённые результаты и запреты администратора на категории не сбрасываются. Других ручных SQL-команд не требуется.

На настроенном сервере с прежними зависимостями:

```bash
cd /opt/session-shope &&
git pull --ff-only origin main &&
systemctl restart session-shope.service &&
systemctl is-active session-shope.service
```

`MINIAPP_URL` остаётся прежним HTTPS-адресом. В этой версии не меняются
сертификаты, маршрутизация reverse proxy, секреты или BotFather.
После обновления открыть Mini App из бота под ID администратора, затем
«Профиль → Админ-панель». Общий доступ включается только отдельной кнопкой
«Доступ Mini App → Включить для всех».

## Проверки

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

`tests/integration_storefront_v2.py` проверяет покупку и однократное списание,
владельца предложения/заказа, переписку и пагинацию, отсутствие тикетов,
права администратора и переключатель доступа на одноразовой MariaDB
`127.0.0.1:13307`. Скрипт использует синтетические данные, не читает `.env`
и удаляет собственную тестовую базу. Платёжные вызовы в этих проверках не идут
в рабочие сервисы. Дизайн и основные сценарии также проверены в Chromium
при ширине 320, 390 и 1440 px; реальная оплата использует прежние интеграции.

`tests/integration_manual_spam.py` проверяет обычную загрузку и ZIP без
автопроверки, ручную очередь, защиту от повторов, FloodWait и миграцию
старых ожидающих загрузок с сохранением балансов. `tests/integration_spam.py`
проверяет конкурентные аренды и запрет продажи во время проверки.

### Проверка SpamBot и заморозки

Обработчик ручных проверок запускается и при отдельном запуске `python -m miniapp.server`.
При отсутствии обновления SpamBot проверяется свежая история после текущего `/start`;
старые ответы не учитываются. При неизвестном результате бот разблокируется, и запрос
повторяется один раз. FloodWait соблюдается, причина ошибки отображается администратору.

При импорте `.session`, ZIP и авторизации по номеру проверяется `freeze_since_date`
из Telegram `help.getAppConfig`. Замороженные аккаунты не экспортируются в товары;
временные файлы удаляются, в отчёте ZIP остаётся только ошибка без сессии.
Если состояние проверить не удалось, импорт отклоняется до повторной проверки.
Это отдельная проверка: обычный спамблок, включая вечный, не означает заморозку.
Уже существующие товары и покупки массово не удаляются.

### Выбор товаров и дополнительные сеансы

В «Товарах» можно отметить до 100 свободных товаров, в том числе на разных
страницах. Доступны общая цена, постановка выбранных в очередь SpamBot и удаление
с подтверждением. Резервы покупателей и история покупок защищены сервером.

Команда администратора `/audit_sessions` в личном чате проверяет непроданные
свободные аккаунты и завершает остальные Telegram-сеансы, сохраняя текущую сессию
магазина. Занятые аккаунты пропускаются. Каждые 50 товаров присылается ZIP с
`report.json`. При неудаче в ZIP включаются исходная StringSession в JSON и
SQLite `.session`, если её удалось экспортировать. ZIP передаётся только
администратору, запустившему команду, и не сохраняется в каталоге сайта.
Дата регистрации берётся из сохранённых данных магазина, её источник указан;
если она неизвестна, значение равно null. Telegram не выдаёт точную дату регистрации.
На новых сессиях Telegram может запрещать завершение других сеансов — такие
аккаунты попадут в отчёт неудач. При неудаче аккаунт сразу скрывается из каталогов бота и сайта. После успешной отправки ZIP администратору он удаляется из общей базы товаров. Если отправка не удалась, скрытый аккаунт сохраняется для повторной отправки командой `/audit_sessions`. Проданные и зарезервированные товары защищены.

### JSON, год регистрации и повторная загрузка

В ZIP теперь допускаются пары `account.session` и `account.json` в одной папке,
до 100 аккаунтов. JSON не более 64 КБ, например:

```json
{"registration_date":"2020-05-14","phone":"+15551112222","user_id":123456789}
```

Поддерживаются `registration_date` и `register_date` в формате YYYY-MM-DD или
Unix timestamp. Дата берётся из данных администратора: Telegram не сообщает её
через API. Поля создания файла/сессии не считаются датой регистрации. Номер и ID,
если указаны в JSON, сопоставляются с фактическим владельцем сессии. Запреты стран
применяются до подготовки строки импорта.

Новый аккаунт получает дату при публикации. Если точно такая же сессия уже есть
в непроданном остатке, предпросмотр предлагает обновить существующий товар.
После подтверждения обновляются дата, телефонный код и Premium, цена сохраняется.
Другие дубликаты по-прежнему отклоняются. В предпросмотре и карточке администратора
видны год и дата. Бот показывает аккаунты старше 30 дней в «С отлёгой», с выбором года.
Дату также можно исправить вручную в редакторе товара. Уже загруженные аккаунты
без JSON/известной даты автоматически стареющими не считаются.
