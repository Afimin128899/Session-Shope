# История изменений

## 1.2.0

- В админ-панель добавлен поиск пользователя по ID или точному @username. В карточке видны балансы и до пяти последних заказов с кнопками открытия.
- Добавлен поиск заказа по номеру покупки (`123` или `#123`), с покупателем, датой, категорией и статусом. Пароли, сессии и коды в результаты поиска не выводятся.
- Журнал фиксирует ID администратора, объект, дату и значения изменений баланса, цены отдельного товара, массовой цены категории и удаления товара. Для просмотра доступны последние записи и переход к более ранним. Время показывается по Москве.
- Изменение и запись в журнале выполняются одной транзакцией: ошибка записи отменяет изменение. Журнал начинается с установки этой версии; прежние действия не восстанавливаются. Другие административные действия пока не включены в журнал.

При запуске `python bot.py` создаётся таблица `admin_audit_log`; пользователю БД необходимо право создания таблиц. Журнал не хранит пароли, коды или сессии. Проверки выполняются локально с заменой внешних сервисов; проверка миграции и сценариев с реальной MySQL и Telegram остаётся отдельным шагом.

## 1.1.0

- В магазине появилась кнопка «Уведомить о поступлении», доступная и при пустом складе.
- Пользователь выбирает категории и может отменить подписку. Подписка действует на одно следующее поступление новых товаров и сохраняется после перезапуска.
- Бот проверяет поступления каждые 30 секунд. Временные ошибки отправки повторяются не раньше чем через 5 минут; при блокировке бота подписка удаляется.
- В карточке покупки, включая завершённые заказы, и сразу после покупки доступна кнопка «Есть проблема». Она открывает поддержку с номером заказа в черновике. Контакт берётся из существующей настройки `support_username` (`@username` или ссылка на профиль Telegram).

При запуске `python bot.py` существующий `init_db()` создаёт таблицу `stock_subscriptions`; пользователь БД должен иметь право создавать таблицы. Отдельный процесс для уведомлений не нужен. Удаление категории также удаляет её подписки.

Уведомления доставляются с повторами при ошибках. Если процесс прервётся между отправкой в Telegram и подтверждением в БД, уведомление может прийти повторно. Уведомление не резервирует товар.

Проверка без обращения к Telegram и внешней базе:

```sh
python -m unittest discover -s tests -v
```
