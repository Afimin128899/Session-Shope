# Локальная диагностика сессий

Админка → Товары → Операции с сессиями → **Диагностика сессий**.
JSON-отчёт отправляется в личный чат администратора, который нажал кнопку.
Перед первым запуском откройте чат с ботом и нажмите `/start`.

Проверяются непроданные товары со статусами `available` и `review`:

- `format_ok`: структура StringSession v1 и адрес соответствуют правилам импорта;
- `missing`: сессия отсутствует;
- `invalid_format`: строка повреждена или имеет неподдерживаемый размер;
- `unsupported_version`: неизвестная версия;
- `invalid_endpoint`: дата-центр, адрес или порт не разрешён текущими правилами;
- `empty_auth_key`: ключ целиком состоит из нулей;
- `duplicate_key`: ключ уже найден у товара `duplicate_of`, даже если порт отличается.

Это локальная проверка, без подключения к Telegram: `format_ok` не подтверждает
авторизацию, владельца, отсутствие блокировки или работоспособность аккаунта.
IPv6 сейчас не входит в список разрешённых сетей существующего импорта.
Данные товаров, резервы и авторизации не меняются.

Отчёт содержит только ID товаров, результаты и накопительные счётчики.
Телефоны, сессии, пароли и отпечатки ключей не отправляются. Не более 500 строк
на файл; дубликаты учитываются и между файлами. Пустой склад тоже даёт отчёт.
Верхний ID фиксируется в начале; это не транзакционный снимок: изменения
существующих товаров во время обхода могут отразиться в результате.

Используются существующие права администратора и блокировка параллельных операций
с сессиями. Миграция базы и новые зависимости не нужны.

Проверка: `python -m unittest discover -s tests -p test_session_diagnostics.py`.
