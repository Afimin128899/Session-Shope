# Тестовый магазин администратора

Вход в боте: **Админ-панель → Тестовый магазин**. В Mini App: **Профиль → Тестовый магазин** либо **Управление магазином → Обзор → Тестовый магазин**. Доступ определяется серверным списком `ADMIN_IDS`; обычным покупателям режим недоступен.

Учебный магазин получает собственные 1 000 виртуальных рублей и 6 тренировочных товаров. Можно:

- Купить товар или корзину, применить учебный код **DEMO10** со скидкой 10%.
- Получить учебный код, завершить заказ и выполнить учебный возврат.
- Создать учебный счёт xRocket, Crypto Pay, Laveshka или Stars и вручную подтвердить его оплату. Учебные Stars сохраняют курс 1 ⭐ = 1,20 ₽.
- После учебного пополнения от 50 ₽ попробовать учебное колесо удачи.
- Сбросить свои учебные покупки, счета и баланс после подтверждения.

Каждый экран явно помечен как тестовый. Реальные телефонные номера, сессии и платёжные API-ключи не используются. Учебные маршруты не обращаются к MySQL, Telethon или платёжным клиентам; хранят отдельное состояние в памяти основного процесса. После перезапуска оно сбрасывается. Учебные данные администраторов разделены, старые кнопки после сброса отклоняются. Сброс учебных данных не меняет рабочие записи.

Стандартный запуск проекта — единый процесс `bot.py`, обслуживающий бота и Mini App. В этом процессе активный учебный режим дополнительно блокирует рабочие изменения данного администратора: старые кнопки покупок, обычные POST/PATCH/DELETE API и подтверждение реального Stars-счёта. Другие покупатели и администраторы продолжают работать. Уже совершённые реальные платежи и возвраты обрабатываются даже при открытом учебном режиме. Счета внешних сервисов, созданные до входа в режим, продолжают существовать у этих сервисов.

Выход: **В рабочий магазин**, кнопка выхода из тестового режима в основном Mini App, либо `/menu`, `/start`, `/cancel` в боте. Если закрыть страницу без выхода, защита рабочих операций сохранится до явного выхода или перезапуска. При раздельном запуске нескольких процессов учебное состояние и блокировка действуют в пределах каждого процесса; для совместной работы бота и Mini App используйте штатный `bot.py`.

## Обновление

```sh
cd /opt/session-shope
git pull --ff-only origin main
sudo systemctl restart session-shope.service
```

Новых зависимостей и миграций нет. Обновите меню через `/start` и заново откройте Mini App.

## Проверки

```sh
python -m unittest discover -s tests
python tests/demo_fixture.py
# В другом терминале:
node tests/demo_browser.cjs
```

Браузерный сценарий использует подписанные тестовые данные администратора и реальный изолированный API на localhost:8087; MySQL и платёжные сервисы для него не запускаются.
