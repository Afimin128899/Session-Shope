# Session Mini App · sbandsub.space

Mini App работает на той же MySQL, что и Telegram-бот. Каталог, реферальные скидки, рублёвый баланс, статусы и заказы общие. Изменения обновляются при возвращении в приложение, вручную и каждые 15 секунд на открытом экране. Для покупки сервер заново читает и блокирует товар, проверяет текущую цену, списывает баланс и сохраняет заказ одной транзакцией.

Интерфейс включает каталог с категориями, поиск и сортировку, подтверждение покупки, историю, просмотр собственного заказа и профиль. Номер до покупки скрыт; пароль доступен только владельцу заказа. Сессии Telegram в браузер не передаются. Получение кода входа, завершение заказа, пополнение и тикеты продолжаются в боте через кнопку с привязкой к покупке.

## Чистый или переустановленный VPS

В SSH-терминале Ubuntu 24:

```sh
sudo apt-get update && sudo apt-get install -y curl ca-certificates
session_installer=$(mktemp)
curl -fsSL https://raw.githubusercontent.com/Afimin128899/Session-Shope/main/install-fresh.sh -o "$session_installer"
sudo bash "$session_installer"
rm -f "$session_installer"
```

Скрипт скачивает проект в `/opt/session-shope`, устанавливает зависимости, локальную
MariaDB, systemd и Caddy. На сервере нужно один раз ввести BOT_TOKEN, Telegram API ID,
API Hash и свой Telegram ID администратора. Токен и API Hash не отображаются.
API ID/Hash берутся на `my.telegram.org`, токен — из BotFather. Не передавайте их в чат.

Домен `sbandsub.space` должен указывать на `31.77.59.42`; порты 80/443 должны быть
доступны извне. Если UFW включён, установщик добавляет правила для 80/443, не меняя SSH. Пароль локальной базы создаётся автоматически. Повторный запуск
сохраняет настройки и базу. Если репозиторий приватный, Git на VPS потребует настроенный
доступ к нему. Скрипт не содержит GitHub-токенов.

Это новая локальная база. Старые балансы, товары и покупки восстанавливаются из
резервной копии отдельно. Опциональные платёжные ключи можно настроить после установки.
Уже установленный проект обновляется обычным `install.sh`, без флага `--fresh`.

## Быстрая установка на Ubuntu 24

В обновлённом каталоге проекта, где уже сохранён рабочий `.env`:

```sh
sudo bash install.sh
```

Установщик подготовит Python-зависимости, systemd и Caddy для `sbandsub.space`.
Параметры: `--service shop.service` для выбора сервиса и `--skip-https` для своего
HTTPS-прокси. Подробности — `deploy/UBUNTU-VPS.md`. На VPS этот скрипт автоматически
не запускается при `git pull`.

## Запуск на существующем сервере бота

Публичный адрес: **https://sbandsub.space**. Нужны HTTPS и доступ сервера к существующей MySQL и Telegram API. Код и локальные тесты не изменяют DNS и не публикуют сайт автоматически.

Добавьте не секретные настройки из `.env.miniapp.example` в окружение существующего процесса бота:

```dotenv
MINIAPP_URL=https://sbandsub.space
MINIAPP_HOST=127.0.0.1
MINIAPP_PORT=8080
```

Перезапустите **один** процесс `python bot.py`. Он запустит API и страницы на порту 8080 и добавит Mini App в меню Telegram и основную клавиатуру. Если `MINIAPP_URL` не задан, бот работает без веб-сервера. Отдельный JavaScript build или npm install не нужен; aiohttp уже есть в requirements.txt.

На HTTPS-прокси существующего сервера направьте запросы домена на `http://127.0.0.1:8080`. Пример блока nginx внутри уже настроенного TLS-сервера:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
}
```

A/AAAA записи `sbandsub.space` должны указывать на нужный сервер, HTTPS-сертификат должен быть действителен. Неверную AAAA-запись необходимо исправить вместе с A-записью. Не заменяйте конфигурацию другого сайта и не запускайте второй polling-процесс с тем же токеном.

Для отдельного веб-процесса существует `python -m miniapp.server`: он подключается к той же базе и не запускает polling. Кнопку в боте добавляет обычный запуск бота с `MINIAPP_URL`.

## Вариант Docker Compose с автоматическим HTTPS

Подготовлены `Dockerfile`, `compose.yaml` и `deploy/Caddyfile` для **sbandsub.space**. На выделенном сервере со свободными портами 80 и 443:

1. Направьте DNS домена на сервер.
2. Сохраните рабочие настройки бота и MySQL в `.env` на сервере, не передавайте токены в чат. База должна быть доступна из контейнера: `127.0.0.1` внутри контейнера означает сам контейнер, а не сервер с MySQL.
3. Остановите прежний polling-процесс, если запускаете этого же бота через Compose.
4. Выполните `docker compose up -d --build` и проверьте `docker compose ps`. Caddy получит и будет обновлять сертификат HTTPS.

Секреты загружаются во время запуска из `.env`; этот файл, Git-метаданные, архивы и файлы сессий исключены из образа. Процесс приложения работает без root. Логи приложения и состояние Caddy сохраняются в отдельных volumes. Общая MySQL остаётся прежней — новая рабочая база не создаётся.

В управляемой облачной среде сборка проверена с переданным CA:

```sh
docker build --secret id=proxy_ca,src="$SSL_CERT_FILE" -t session-shope .
```

Обычный сервер без корпоративного прокси может собирать образ без секрета CA. Проверка TLS не отключается.

## Авторизация и ограничения

API принимает `Authorization: tma <Telegram.WebApp.initData>`. HMAC проверяется на сервере с `BOT_TOKEN`; неподписанные данные и сессии старше часа отклоняются. При истечении сессии приложение нужно открыть из бота заново. Токен бота не передаётся клиенту, initData не записывается в localStorage или URL.

API проверяет владельца покупок, поддерживает режим технических работ и обязательную подписку. При ошибке проверки подписки доступ не открывается. На запросы пользователя действует ограничение частоты, а покупка требует явного подтверждения цены. Оплата с баланса работает в RUB; USDT отображается отдельно и не списывается вместо рублей.

`GET /api/health` — проверка работоспособности веб-процесса, а не проверка подключения к MySQL. Без авторизации браузер показывает приглашение открыть приложение из Telegram, без каталога и приватных данных. Отдельного демонстрационного входа в рабочем API нет.

## Проверки

```sh
python -m unittest discover -s tests -v
```

HTTP-тестам нужны локальные сокеты. Интеграция запускается только на отдельной временной MySQL на `127.0.0.1:13307`, с root без пароля для локального теста:

```sh
python tests/integration_miniapp.py
```

Скрипт не загружает `.env`, создаёт новую случайную тестовую базу и удаляет её после завершения. Проверяет авторизацию, конкурентную покупку, единый баланс, реферальный бонус, принадлежность заказов, устаревшие цены и синхронизацию с ботом.

Браузерная проверка на тех же изолированных данных:

```sh
python tests/integration_miniapp.py --serve
# В другом терминале, с установленными Playwright и Chromium:
node tests/miniapp_browser.cjs
```

В тесте Telegram SDK заменяется тестовым объектом с подписанными тестовыми данными; каталог и покупка используют реальную временную MySQL. Рабочий API не содержит этих тестовых обходов. Скриншоты сохраняются в `/tmp/session-miniapp-preview`.
