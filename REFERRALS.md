# Реферальная программа · 5.9.0

Настройки по умолчанию: 3 ₽ пригласившему за нового пользователя, 5% с подтверждённых пополнений, 5% с фактически оплаченных покупок и общий лимит наград 30 ₽ в сутки по Москве. Ранее существовавшая скидка приглашённому 5% сохранена и также настраивается администратором.

## Управление

В боте: **Админ-панель → Настройки → Реферальные награды**. В Mini App: **Управление магазином → Настройки → Изменить настройки → Реферальные награды**.

Можно менять награду за регистрацию (0–10 000 ₽), проценты пополнений/покупок (0–100%), скидку приглашённому (0–100%) и суточный лимит (0–10 000 ₽). Допускаются два знака после запятой. 0 отключает соответствующую награду/скидку; суточный лимит 0 отключает все реферальные начисления. Новые значения применяются к будущим операциям. Ранее полученные суммы и снимки возвратов не пересчитываются. Изменения записываются в административный журнал.

В боте награды и собственная ссылка находятся в **Мой профиль → Реферальная система**; список — **Мои рефералы**. В Mini App — **Профиль → Реферальная программа**. Показаны ссылка для копирования, число приглашённых, начисленная сумма с учётом возвратов, суточный лимит/остаток и список приглашённых. Пагинация показывает по 20 пользователей: username и Telegram ID; телефоны, баланс, покупки, пароли и сессии приглашённых не публикуются. Пользователь видит только собственный список.

Администратор может открыть список любого пользователя: в боте **Реферальные награды → Рефералы пользователя** и ввести ID; в Mini App **Покупатели → поиск по ID → Рефералы пользователя**.

## Лимит 30 ₽ в день

Лимит общий для награды за регистрацию, пополнений и покупок на одного пригласившего. День меняется в 00:00 по Москве. Например, если сегодня уже начислено 28 ₽, следующая рассчитанная награда 5 ₽ даст только оставшиеся 2 ₽. Остаток сверх лимита не переносится на следующий день и не выдаётся повторной проверкой счёта.

Возвраты отменяют реально выданную награду, но не восстанавливают суточный лимит. При уменьшении лимита ниже уже начисленной суммы старые деньги не отнимаются: новые начисления останавливаются до нового дня или увеличения лимита. Сохранённые начисления по старым заказам за сегодняшний день учитываются при первом расчёте квоты после обновления; выплаты задним числом не создаются.

Счётчик хранится в MySQL, общий для бота, Mini App и фоновых обработчиков. Параллельные пополнения или покупки не обходят лимит. Квота и награда изменяются в одной транзакции вместе с оплатой/заказом.

## Блокировка по Telegram ID

В боте: **Реферальные награды → Блокировки наград → Заблокировать ID**. Отправьте числовой ID; причину можно добавить через пробел. Для снятия — **Разблокировать ID**.

В Mini App: **Настройки → Блокировки наград**. Введите ID, при желании причину, выберите блокировку или разблокировку. В списке заблокированных ID есть кнопки снятия блокировки. Можно заранее заблокировать ещё не зарегистрированный ID.

Блокировка отключает получение этому пользователю реферальных наград. Она не блокирует регистрацию, приглашение пользователей, настоящий платёж, покупку, возврат или личный баланс. Старые выданные награды не списываются только из-за блокировки; обычные возвраты продолжают отменять соответствующие награды. Пропущенные во время блокировки награды не начисляются задним числом после разблокировки. Причины доступны только администраторам.

Запись блокировки синхронизирована с кошельком получателя. После её сохранения ожидающие начисления должны увидеть новую блокировку. Все операции блокировки/разблокировки журналируются с настоящим ID администратора.

## Когда начисляются деньги

Награда за нового пользователя создаётся только при его первой регистрации по ссылке. Повторный `/start`, смена пригласившего, собственная ссылка и ссылка на неизвестного пользователя не создают дополнительной награды. Старым зарегистрированным пользователям новая награда задним числом не выплачивается. При обязательной подписке приглашение сохраняется на время её подтверждения.

Процент пополнения считается от оплаченного номинала, без первого бонуса 10%, реферальных наград, промокодов и колеса удачи. Поддерживаются Crypto Pay, xRocket, Laveshka, Platega и Telegram Stars. Для Stars используется рублёвая сумма по фиксированному курсу 1 ⭐ = 1,20 ₽; два разных действительно оплаченных charge ID учитываются отдельно, повтор одного — нет.

Процент покупки считается после скидки приглашённому, опта и промокода. Фактически выданная награда сохраняется в заказе, включая уменьшение до суточного остатка или ноль из-за блокировки. При возврате используется именно сохранённая сумма, даже если администратор уже изменил проценты.

Возврат Stars отменяет сохранённую награду этого charge ID ровно один раз. Возврат до поступления оплаты не создаёт награды при поздней квитанции. Если награда уже потрачена, баланс пригласившего может стать отрицательным: это не мешает учесть настоящий возврат покупателя. Автоматический возврат внешних крипто/СБП-счетов этим обновлением не добавлен.

## Обновление и проверка

На VPS:

```sh
cd /opt/session-shope &&
git pull --ff-only origin main &&
systemctl restart session-shope.service
```

Схема добавляется при запуске: новые поля `referral_settings`, таблицы `referral_rewards`, `referral_daily_totals` и `referral_blocks`. Старые заказы, связи приглашений и суммы сохраняются. Новые таблицы включены в проверку восстановления резервных копий. Новых платёжных ключей или переменных `.env` не требуется.

Проверки разработки: `python -m unittest discover -s tests`, затем `python tests/integration_referrals.py` и `python tests/integration_miniapp.py --admin`. Интеграционные сценарии используют одноразовую MariaDB на `127.0.0.1:13307` и тестовые ответы, без рабочих платежей. Для Chromium: `python tests/integration_referrals.py --serve`, затем `node tests/referrals_browser.cjs`.
