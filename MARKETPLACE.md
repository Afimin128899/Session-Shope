# Sband ACCS 4.0

Mini App использует ту же базу, пользователей, баланс и заказы, что и бот. Никакого переноса аккаунтов между ними не требуется.

- В карточке видны ID товара `#01` (для товара 1; далее `#02`, `#123`) и настоящий Telegram user ID. Telegram ID сохраняется при новой авторизации и импорте `.session`; для старых строк без этого поля отображается «Не сохранён». Значение не вычисляется из номера телефона.
- Поиск принимает название категории, ID товара и Telegram ID. Фильтры цены учитывают личную скидку. Сортировка по скидке использует сохранённую предыдущую цену и личную скидку; прежняя цена появляется только после реального снижения администратором.
- ♡ сохраняет аккаунт и включает уведомления в боте о снижении базовой цены. Удаление из избранного отключает их. Это не резервирование.
- «+» добавляет аккаунт в корзину и резервирует на 5 минут. Обновление страницы и повторный клик не продлевают действующий резерв. После истечения ✓ повторно резервирует товар, если он ещё свободен. Ограничение — 20 аккаунтов. Чужой действующий резерв защищён и в Telegram-боте.
- Корзина оплачивается целиком с рублёвого баланса после подтверждения. Если хотя бы один резерв истёк, цена изменилась или средств не хватает, списания и выдачи не происходит. Повторная отправка запроса не оплачивает проданный товар второй раз.
- Пополнение доступно в профиле и верхней панели. Отображаются только сервисы с настроенными ключами Crypto Pay, xRocket, Lave Pay. Новые счета сохраняются до показа ссылки. Сервер проверяет их каждые 15 секунд, при ошибках — с увеличением интервала до часа. Подтверждение требует ответа API платёжного сервиса, правильного ID, владельца и суммы. Ручная проверка в боте остаётся и использует ту же защиту от двойного зачисления.
- Счета, созданные до обновления, отсутствуют в новой очереди: используйте старую кнопку проверки в боте. Закрытие Mini App не прекращает серверную проверку. Сохранение клиентского окна счёта после повторного открытия пока не предусмотрено.
- Администраторы получают отчёт за предыдущий день в 09:00 МСК: продажи, пополнения без бонусов, возвраты отдельно по валютам и текущий остаток. Ручная кнопка — «Отчёт за вчера» в админке. При запуске после 09:00 отправляется вчерашний отчёт; пропущенные более ранние дни автоматически не рассылаются. При сбое доставки будет повторная попытка. При аварии между отправкой в Telegram и сохранением статуса возможен повтор уведомления.

## Обновление VPS

Изменения в GitHub сами по себе не обновляют VPS. Для уже установленного `/opt/session-shope` и сервиса `session-shope.service`:

```sh
cd /opt/session-shope
git pull --ff-only origin main
sudo systemctl restart session-shope.service
systemctl is-active session-shope.service
curl --fail https://sbandsub.space/api/health
```

До обновления рекомендуем запустить настроенный сервис копирования `sudo systemctl start session-shope-backup.service`. Миграции создаются при старте бота; существующие покупки и балансы сохраняются. Схема совместима с предыдущим кодом. Для отката сначала остановите бот, выберите прежний коммит и запустите тот же сервис. Активные резервы предыдущая версия не учитывает — откатывайте после их истечения.

Если сервис не поднялся: `journalctl -u session-shope.service -n 60 --no-pager`. Отправлять токены и содержимое `.env` не нужно.

## Копии вне VPS

Внешнее хранилище пока не выбрано и не подключено. Локальные зашифрованные копии и проверка восстановления описаны в [BACKUPS.md](BACKUPS.md). Подключение S3/SFTP подготовлено через `deploy/connect_backup.py`; ключи вводятся непосредственно на VPS. Конфигурация меняется только после успешной первой копии и проверки выбранного репозитория. Этот шаг выполняется позже, когда появится хранилище.

# Обновление 4.1: гарантия, отзывы и история

## Гарантия и характеристики

Новые аккаунты, добавленные через бота, получают **24 часа гарантии**. Ранее загруженные товары и старые покупки автоматически гарантию не получают: у них отображается «не указана» / «срок не сохранён». В админ-карточке товара кнопка «Характеристики и гарантия» задаёт срок 0–8760 часов (0 — без гарантии), проверенную дату регистрации, Premium и описание. Неизвестные значения задаются `?` и так и отображаются покупателю. Возраст не вычисляется по ID. Premium сохраняется при проверке сессии и может впоследствии измениться; наличие сохранённого пароля обозначается «пароль указан», без обещания актуальности 2FA.

При покупке сервер сохраняет характеристики и условия гарантии в заказе. Срок отсчитывается от оплаты; изменение товара администратором не меняет уже выданные заказы. Mini App показывает характеристики до оплаты и срок гарантии при подтверждении корзины. Если срок изменился после формирования корзины, покупку нужно подтвердить заново.

В деталях заказа в боте и Mini App есть кнопка гарантийного обращения. Право на обращение и срок проверяются повторно **при отправке**, а не только при открытии формы. Заявка попадает в существующую переписку поддержки с отметкой времени. Истечение гарантии не закрывает уже принятую заявку и не отключает обычную поддержку. Гарантия относится к проблемам со входом; решение о возврате принимает поддержка после проверки. Автоматического обещания возврата нет.

## Отзывы

Один отзыв на покупку, оценка 1–5, текст до 500 символов; покупатель может изменить его в деталях заказа. Другой пользователь не может оставить отзыв о чужом заказе. Возврат покупки не удаляет её настоящий отзыв. Публичный список показывает оценку и текст без имени, Telegram ID, номера заказа или аккаунта. Номер и известный сохранённый пароль самого аккаунта в тексте отклоняются; остальные личные данные не следует писать в публичный отзыв. Разметка отзыва показывается как обычный текст.

## Промокоды

Прежние коды продолжают пополнять рублёвый баланс. В Mini App: профиль → «Активировать промокод» → проверка суммы → подтверждение активации. Активация общая с ботом, повторное зачисление исключено.

Новая кнопка админки «Создать промокод скидки» принимает `SBAND10 10 100` — имя (до 40 байт UTF-8), процент, общий лимит. Каждый покупатель может использовать код один раз. Процент применяется после личной скидки к каждой позиции, с округлением до копейки. В окне оплаты корзины: ввести код, проверить условия и новую сумму, затем подтвердить покупку. Лимит и факт использования сохраняются одной транзакцией с покупкой. Ошибка или отмена покупки не расходует активацию. При возврате возвращается фактически оплаченная сумма; использованный промокод не восстанавливается.

## Пользовательская история действий удалена в 4.2.1

Пункты истории удалены из главного меню бота, профиля и Mini App; прежний пользовательский API недоступен. Старые кнопки сообщают об удалённом разделе. Журнал действий администратора, покупки, оплаты, возвраты и финансовые записи в базе сохранены.

## Независимые уведомления о сбоях

Для установленного VPS после обновления и запуска бота выполните:

```sh
cd /opt/session-shope
sudo .venv-miniapp/bin/python -m deploy.setup_monitor --project /opt/session-shope --service session-shope.service
systemctl status session-shope-monitor.timer --no-pager
```

Новая установка через `install.sh` включает таймер автоматически. Монитор каждые 2 минуты проверяет systemd бота и Caddy, локальный Mini App, доступность базы, свободное место, задания backup и повторные ошибки API проверки оплат. Он работает отдельным root-сервисом и продолжает проверку, когда процесс бота остановлен. Уведомления отправляются ID из `ADMIN_IDS`; секреты и тела ошибок платёжных API в сообщения не входят. Одна проблема напоминает о себе не чаще раза в час; после исправления приходит восстановление. Состояние хранится приватно в `/var/lib/session-shope/monitor`.

Ошибка одного неоплаченного счёта не считается аварией. После трёх ошибок проверки API провайдера создаётся инцидент; успешная проверка сбрасывает его. Оба backup-сервиса проверяются по результату systemd; успешное создание копии сохраняет отметку для проверки давности в 30 часов. Внешнее хранилище по-прежнему не подключено.

Полное отключение VPS или невозможность связаться с Telegram этот же VPS сообщить не сможет — для этого нужен внешний монитор. Нестандартные порт Mini App, HTTPS-прокси и имена backup-сервисов требуют адаптации проверки; стандартная установка использует 8080, Caddy и `session-shope-backup*`.

# 4.2: каталог и инструменты магазина

- Каталог фильтруется по Premium и минимальному возрасту (30, 180, 365, 1095 дней). Неизвестные дата регистрации/Premium не попадают в соответствующий фильтр; возраст опирается на сохранённую дату, а не на Telegram ID.
- Полная карточка содержит условия, характеристики, инструкцию входа и кнопку добавления в корзину. «Поделиться» создаёт ссылку на бота `?start=product_ID`; бот выдаёт кнопку Mini App с нужной карточкой. Наличие проверяется при открытии, секретов в ссылке нет.
- Оптовая скидка **15% от 500 ₽** считается от суммы после личной скидки, до промокода. Округление — по каждой позиции до копейки. Сервер заново проверяет итог; старые клиенты без подтверждённой итоговой суммы должны обновить Mini App для оптовой покупки.
- Поиск своих заказов принимает ID, страну/название категории или начало даты `ГГГГ-ММ-ДД`. Чужие заказы не возвращаются.
- В обращении Telegram можно отправить фотографию/скриншот с подписью до 500 символов. Поддержка и владелец видят кнопку просмотра в переписке. Вложения хранятся как Telegram file ID, без публичных URL; загрузка файлов через Mini App не добавлялась. В Mini App есть переход к боту для скриншота.
- База знаний доступна в профиле Mini App, поиск работает по заголовкам и тексту. Часы поддержки и ориентир ответа задаёт администратор; пока график не указан, приложение не обещает придуманный срок.
- У свободных товаров обновлён дизайн карточек, фильтров и полной карточки; на узком экране — одна колонка.

## Администратору

В админке кнопка «Инструменты магазина» и команда `/shop_tools` показывают команды. Изменения подготавливаются сообщением, затем подтверждаются отдельной кнопкой; чужой пользователь выполнить их не может.

```
/bulk_edit 12,13 price 100
/bulk_edit 12,13 warranty_hours 48
/bulk_edit 12,13 features_note Проверенное описание
/replace 123 456 Причина замены
/shop_rules 500 15 600 3
/support_schedule Ежедневно 10:00–22:00 МСК | Обычно до 24 часов
/refund_queue
```

Числа `shop_rules`: минимальная сумма опта ₽, процент, порог двойного согласования возвратов ₽ (0 отключает), порог низкого остатка. Пример расписания — только пример; укажите фактические часы команды.

Массовое редактирование работает до 100 разных ID одной транзакцией. Если хотя бы один товар уже продан или отсутствует, весь пакет отклоняется. Цена сохраняет историю сравнения для скидок; условия уже проданных заказов остаются прежними.

Замена доступна один раз по заказу с действующей гарантией либо заявкой, принятой в срок. Новый аккаунт должен быть свободен и той же категории, без чужого резерва. Прежний аккаунт снимается с продажи, его пароль и сессия очищаются. Заказ получает новые данные без повторного списания. Исходные оплаченная сумма, гарантийный срок и характеристика на момент первоначальной покупки сохраняются; история замены — в отдельной записи и журнале администратора.

Возврат от **600 ₽** требует другого администратора. Для других валют при включённом пороге согласование обязательно независимо от числовой суммы: пересчёт курса не угадывается. Инициатор не может согласовать собственную заявку. Ожидающие заявки доступны через `/refund_queue`; без второго ID в `ADMIN_IDS` крупный возврат останется в ожидании. После согласования действует прежняя атомарная защита от повторного зачисления. Низкоуровневая функция возврата используется внутренними тестами/операциями; Telegram-процесс всегда проходит через согласование.

Остаток до 3 шт. по активной категории вызывает уведомление администраторам. Учитывается весь непроданный остаток, включая короткие резервы. Повтор — не чаще раза в сутки, после пополнения выше порога предупреждение сбрасывается. При недоставке повтор будет примерно через час. Нужны запущенный бот и возможность отправлять сообщения администраторам.

Обновление VPS: сначала резервная копия, `git pull --ff-only origin main`, перезапуск прежнего `session-shope.service`. Миграции добавляются при запуске. Новые таблицы и ссылки на вложения входят в проверку восстановления базы; сами фото хранит Telegram, поэтому восстановление SQL не гарантирует бессрочную доступность файла у Telegram.
