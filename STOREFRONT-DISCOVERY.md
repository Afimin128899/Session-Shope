# Обновление витрины

Корневая страница магазина использует `miniapp/storefront_v2`. Обновление добавляет
оформление первого экрана и карточек, сортировку каталога по цене, наличию и названию,
очистку поиска, кнопку обновления и отдельный экран пустой выдачи.

Клавиша `/` переводит фокус в поиск, если пользователь не вводит текст и не открыт
диалог. Первая ссылка при навигации клавиатурой позволяет пропустить шапку.
Выбранный вид аккаунтов доступен скринридеру через `aria-pressed`.

Ревизия запроса меняется сразу при вводе и переходе на другую вкладку: старый ответ
не подменяет результаты более нового поиска. Сортировка применяется к возвращённым
сервером категориям. Рекомендуемый порядок сохраняет серверный порядок.

Новый CSS загружается после общей темы, из того же источника, без внешних ресурсов.
Стили общей админки и устаревшей витрины не меняются. Учитываются настройки
уменьшения движения. Изменения не требуют миграции базы данных.

Проверки:

```sh
node --check miniapp/storefront_v2/app.js
node tests/ui_polish_browser.cjs
PYTHONPATH=tests:. python -m unittest test_storefront_v2 test_miniapp_upgrade
```

Браузерный тест работает с локальными фикстурами API: размеры 320, 390, 768 и
1440 пикселей, поиск и его очистка, сортировка, запоздалый ответ, безопасный вывод
текста запроса, покупка, профиль, платежи, сообщения и операции админки.
Рабочие платежи и Telegram не вызываются. Серверные тесты используют подмены базы.

Публикация ветки или PR не обновляет VPS. Для установки используется существующий
процесс обновления проекта после просмотра изменений.

## Следующий этап

- Выбор плиток или компактного списка сохраняется вместе с сортировкой и видом
  аккаунтов. localStorage хранит только эти три настройки; поиск и данные аккаунтов
  в него не записываются. Недоступное хранилище не мешает работе приложения.
- Сортировка использует последний успешный ответ для текущего запроса, без повторного
  обращения к API. Кнопка обновления всегда запрашивает актуальное наличие.
- В заголовке показана выбранная страна. Возврат к странам восстанавливает поиск,
  с которым пользователь открыл страну.
- Над каталогом показано суммарное наличие из текущего ответа сервера.

## Подбор по цене и наличию

Условия «Начальная цена до» и «Наличие в категории» фильтруют загруженный каталог
без дополнительных запросов. Цена сравнивается с `min_price`: это начальная цена
категории, а не обещание цены любого аккаунта в ней. Под фильтром показывается
пояснение; точную сумму по-прежнему определяет сервер перед оплатой. Суммарное
наличие относится ко всем товарам выбранных категорий, а не только к товарам
в пределах бюджета. Сброс убирает поисковый запрос и оба условия; он сохраняет
выбранную страну, вид аккаунтов, сортировку и отображение.

На экранах до 420 px плитки идут в одну колонку с ценой и кнопкой рядом.

## Компактная витрина

Первый экран уменьшен: реферальное предложение остаётся доступным, но занимает
меньше места на телефоне. Расширенные условия, сортировка и переключение вида
собраны в сворачиваемый блок «Настроить подбор». Количество результатов и наличие
видны и при закрытом блоке. Выбранные ограничения отображаются отдельными кнопками
со сбросом одного условия.

Быстрый подбор доступен без открытия настроек: все варианты, начальная цена
100 ₽ и ниже, наличие от 10 товаров, сортировка по цене. Он не меняет поисковый
запрос или выбранную страну. Каждая кнопка показывает выбранное состояние через
`aria-pressed`. Быстрый подбор использует загруженный ответ; обновление каталога
по-прежнему запрашивает сервер.

Этот этап вместе с последующими коммитами после первого PR собран в ветке
`codex/catalog-workspace`. Для уже установленного проекта:

```sh
cd /opt/session-shope
git fetch origin
git switch codex/catalog-workspace
git pull --ff-only origin codex/catalog-workspace
sudo bash install.sh
```

После слияния нового PR можно использовать обычное обновление `main`.
Публикация PR сама по себе не обновляет приложение на VPS.
