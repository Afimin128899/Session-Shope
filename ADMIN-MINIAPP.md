# Sband ACCS 5.0 — админка и массовый импорт

В Mini App появился раздел «Управление» для пользователей из `ADMIN_IDS`. На компьютере он находится в боковой навигации, на телефоне — в профиле. Авторизация использует подписанные данные Telegram и проверяется на каждом серверном запросе. Покупателям административный API возвращает 403, даже если вручную показать кнопку в браузере.

## Разделы

- **Обзор:** остаток, заказы, покупатели, активные обращения, возвраты на согласовании и продажи за текущий день МСК отдельно по валютам.
- **Товары:** поиск по ID, телефону и категории; статусы, редактирование цены, категории, гарантии, даты регистрации, Premium и описания. Изменяются только свободные товары без действующего резерва покупателя. Массовое изменение цены, гарантии или описания проходит одной транзакцией. Удаление требует подтверждения и не затрагивает историю покупок.
- **Импорт:** загрузка ZIP, проверка, выбор строк, назначение цены/категории/гарантии и подтверждение публикации. Последние черновики доступны повторно.
- **Заказы:** поиск по номеру, покупателю и username, просмотр суммы/статуса, возврат на исходный баланс и гарантийная замена. Сессии и пароли в административных таблицах не выдаются.
- **Поддержка:** переписка с пагинацией, ответ, закрытие и просмотр скриншотов. Фото передаётся через авторизованный серверный запрос; Telegram token в URL браузера не передаётся.
- **Возвраты:** очередь согласований; правило второго администратора сохраняется. Самосогласование запрещено. При временной ошибке кнопку можно повторить — двойной возврат не произойдёт.
- **Покупатели:** поиск по Telegram ID или точному username, изменение рублёвого/USDT-баланса с подтверждением. Веб-операция получает уникальный ключ; повтор того же запроса не меняет баланс второй раз.
- **Категории:** создание, переименование и скрытие.
- **Промокоды:** создание скидочных/балансовых кодов и отключение новых активаций с сохранением использований.
- **Настройки:** оптовые условия, порог согласования возвратов, порог низкого остатка, график поддержки и техработы.
- **Журнал:** прежний административный аудит. Удалённая пользовательская история действий не возвращается.

Важные операции подтверждаются формой с конкретными значениями. Веб-админка использует ту же базу, заказы, поддержку и защиту возвратов, что и бот; команды бота остаются доступными.

## Формат массовой загрузки

1. Создайте ZIP с файлами SQLite `.session` Telethon. Подкаталоги допустимы. Другие файлы, JSON-манифесты и вложенные архивы не поддерживаются — их нужно убрать из ZIP.
2. Максимум: **8 МБ ZIP, 100 сессий, 1 МБ на файл и 32 МБ распакованных данных**. Ссылки, выход за каталог, зашифрованные ZIP и чрезмерное сжатие отклоняются. Файлы не извлекаются по пользовательским путям.
3. Выберите архив. Сервер проверяет сессии по очереди: авторизована ли сессия, доступен ли профиль, телефон, Telegram ID, Premium. До соединения проверяется, что SQLite содержит таблицу сессии, ключ и адрес известной сети дата-центров Telegram; произвольные адреса запрещены. Требуются рабочие Telegram API ID/Hash и доступ VPS к Telegram.
4. Предпросмотр показывает готовые строки, ошибки и дубликаты. Секретные session strings и существующие пароли API не возвращает. Неизвестные пароли 2FA не извлекаются из `.session`: если пароль известен администратору, его можно ввести в соответствующее скрытое поле перед публикацией; иначе поле остаётся неизвестным.
5. Выберите только нужные готовые строки. Задайте категорию, цену и гарантию каждой строке либо примените общие значения. По умолчанию гарантия 24 часа. Подтвердите итоговый список.
6. Публикация выбранного пакета атомарна: при неверной категории, конфликте дубликата или ошибке записи ни один выбранный аккаунт не добавляется. Повторное подтверждение уже опубликованного черновика запрещено.

Дубликаты проверяются по подтверждённому Telegram ID, нормализованному телефону и отпечатку сессии, включая уже проданные аккаунты. Блокировки идентификаторов используются также существующей одиночной загрузкой бота. Старые дубликаты автоматически не удаляются. Если до публикации такой же аккаунт был добавлен другим администратором, пакет отклоняется целиком; отмените черновик и загрузите исправленный архив.

## Сроки, хранение и ограничения

Черновик принадлежит загрузившему администратору и действует **1 час**. Другой администратор его не видит и не публикует. После публикации или отмены session strings черновика очищаются; невыбранные строки не публикуются. Просроченные и неудачные черновики очищает серверная задача примерно раз в 5 минут, пока Mini App работает. Эти данные имеют ту же чувствительность, что сессии в основной базе; доступ к БД и копиям должен оставаться закрытым. Копии restic зашифрованы, очистка черновика не удаляет его из уже существующей резервной копии.

Одновременно проверяются до двух архивов на процесс и один архив на администратора. Исходные файлы обрабатываются в приватном временном каталоге и удаляются при завершении/отмене задачи; после аварийной остановки остатки старше часа очищаются отдельным проходом. Проверка продолжается при переходе на другую вкладку Mini App. При перезапуске процесса незавершённая проверка не возобновляется автоматически — отмените черновик и загрузите архив снова. Проверка подтверждает состояние сессии на тот момент; она не гарантирует, что сессия не будет впоследствии отозвана.

Автоматические тесты используют локальную замену проверяющего Telegram, реальную тестовую MariaDB и настоящий HTTP API. Производственные аккаунты и платёжные сервисы в тестах не используются; живой импорт нужно проверить своим тестовым аккаунтом на VPS с настроенными ключами.

## Обновление VPS

```sh
cd /opt/session-shope
sudo systemctl start session-shope-backup.service
git pull --ff-only origin main
sudo systemctl restart session-shope.service
curl --fail --retry 10 --retry-connrefused --retry-delay 2 https://sbandsub.space/api/health
```

Новых внешних зависимостей нет. Миграции добавляют таблицы черновиков, идентификаторов и ключей веб-операций при запуске бота. Они включены в проверку восстановления копий. Административные ID по-прежнему меняются только в серверной конфигурации, а не через браузер. Открывайте приложение заново из Telegram, если срок подписи истёк. До обновления VPS изменения GitHub на работающий сайт не влияют.
