# TG Market: витрина и центр управления

Новый интерфейс встроен в действующий Session-Shope. Маршрут `/` обслуживает
`miniapp/storefront_v2/index.html`; отдельная страница админки `/admin-app`
остаётся доступной. Верхняя кнопка открывает ту же админку внутри витрины.
Все разделы на русском. Вспомогательные роли сохраняют прежние ограничения.

## Витрина

- Палитра Telegram Night: #0E1621 / #17212B / #2AABEE, Inter и JetBrains Mono.
  Шрифты загружаются из Google Fonts с локальным системным fallback. CSP разрешает
  только конкретные домены шрифтов; inline-скрипты и произвольные CDN не добавлены.
- Подбор по шести GEO, известной дате регистрации, Premium, статусу спамблока и
  наличию пароля 2FA. Возраст не выводится из времени создания сессии.
- Наличие и таблица итогов для 1–20 аккаунтов поступают с сервера. Цена каждого
  аккаунта, реферальная скидка и оптовый порог берутся из действующей базы.
  Процент опта применяется с округлением каждого товара, как при списании.
- Оформление создаёт реальный резерв на пять минут через существующую корзину.
  Итог подтверждается до списания. Токен привязан к пользователю и кошельку
  магазина, имеет срок действия и удаляется после успешной покупки.
- Покупка выполняется атомарно существующим `checkout_cart`, без новых балансов
  или изменения платёжных провайдеров. Товар, цена, гарантия и резерв перепроверяются.
- Оплата с баланса; криптовалюта и карта ведут в существующий процесс пополнения.
  Не настроенные способы оплаты не имитируются.
- Session + JSON выдаётся в ZIP для каждого оплаченного заказа: Telethon SQLite,
  JSON с метаданными и 2fa.txt при наличии пароля. Скачивание требует Telegram
  авторизации и владения заказом. Статус и доступ проверяются до и после создания
  архива. Возврат, завершение и отзыв доступа закрывают выдачу.
- TDATA отключён с объяснением: сервер пока не умеет создавать такой архив.
  Pyrogram-совместимость не заявляется для Telethon SQLite. Действующий вход
  через код сохраняется. Проверка спамблока отображает последний результат,
  а не обещание новой сетевой проверки перед каждой покупкой.
- Срок гарантии сохраняется из конкретного товара. Фиктивные «30 минут»,
  количество завершённых покупок и показатели прокси не добавлены.

## Администрирование

Четыре группы по пять действий: товары; заказы/финансы; пользователи/поддержка;
система/безопасность. KPI используют реальную выручку за день (МСК), наличие и
количество возвратов на согласовании. Прямое подключение чекера обозначено Direct.

Реальные операции: загрузка ZIP с drag-and-drop, очередь SpamBot, цены категорий,
оптовые условия, экспорт сессий в личный чат администратора, выборочное удаление
свободных товаров с подтверждением, поиск заказов, гарантийная замена, возврат,
изменение баланса с ключом операции, промокоды, глобальные блокировки, сообщения,
режим обслуживания и журнал. Детали заказов и отзыв доступа из предыдущего
изменения сохранены.

Инфраструктурные границы показаны явно:

- Пул прокси не подключён в текущем `services/telethon_factory.py`; состояние
  не подменяется выдуманным числом живых прокси.
- Платёжные ключи и токен бота задаются в окружении сервера. Браузер показывает
  состояние способов оплаты и необходимые имена переменных, не секреты.
- Вывод выполняется в кабинете платёжного провайдера. Общая выручка и клиентские
  остатки не выдаются за свободную прибыль к выводу.
- Рассылка открывает существующий процесс в /admin бота с предпросмотром,
  подтверждением и возможностью остановки.
- Резервные копии управляются существующим restic на сервере (BACKUPS.md).
  Новый публичный endpoint для полной базы и ключа шифрования не создаётся.

Встроенная админка использует Telegram WebApp родителя только при совпадении
origin; обычное открытие и внешние Telegram iframe сохраняют рабочий fallback.
Сообщение для прокрутки к админскому диалогу проверяет origin и окно-источник.
CSP допускает встраивание только в тот же origin и доверенные Telegram origins.

## Проверка и запуск

Тесты работают без реальных оплат, базы и Telegram-сессий:

```bash
PYTHONPATH=tests:. python -m unittest test_configurator test_storefront_v2 test_order_access test_admin_tools test_admin_web test_tickets test_miniapp test_shop_navigation -q
node tests/tg_market_browser.cjs
```

Браузерный тест проверяет 320/360/390/768/1440 px, отсутствие горизонтального
переполнения, фильтры, количество, оплату, скачивание ZIP, переключение рабочих
пространств и все 20 административных кнопок на изолированных fixtures.
Скриншоты сохраняются в `/workspace/session-shope-previews/`.

Для запуска обновите код и перезапустите приложение штатным способом. Для
полноценной работы нужны действующие Telegram credentials, база и ранее
настроенные платёжные провайдеры. Инициализация схемы из изменения отзыва
доступа должна отработать до использования новых полей заказов. Никакие новые
реальные ключи или демонстрационные данные в базу не записываются.
